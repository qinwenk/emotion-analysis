# 输出模式定义

## 升级目标与适用范围

保留本 skill 的核心用途：依据聊天证据和分级口述，分别解释**亲近或吸引、恋爱意愿、相处适配、持续经营**，识别关键节点、情绪场景与当前卡点，按实际诉求提供可执行建议。升级目标是让结论可追溯、建议贴合已发生的事、反馈可评估，减少模板化复述和未经支持的确定语气。

适用于完整关系分析、单次互动解读、用户纠正、后续追踪和一句回复。证据检索阶段使用本定义的来源、角色与事件状态约束完成交接，不提前替分析阶段作结论。只要求数据导入、工具维护或 skill 优化时，交付所要求的结果，不附赠关系分析。

这是输出契约，不新增数据获取、身份认证、临床诊断、评分算法或记忆系统。可用能力以实际安装的参考、工具契约及执行结果为准。用于优化的试验对话、案例或历史报告仅作为参照；未请求重分析或修订时，不改写这些材料，也不把其中的人名、关系结论或口述当成通用规则。

## 输出结构与顺序

以下是逻辑顺序，不是每轮必填的五个标题。按问题删减，证据不足时缩小结论，不能用模板补齐事实。

1. **先给核心回答。** 通常用 1–3 句直接回答当前问题，明确证据支持到哪一层。存在关键歧义时，给最有支持的解释及会改变行动的重要竞争解释；不强凑正反各半。用户只要一句回复时先交付可用句子；用户只想分析时，不擅自把目标变成表白、推进、挽回或退出。
2. **用关键事件说明理由。** 通常选 2–4 个最有判别力的事件，纳入重要反证或修复。按“发生了什么 → 双方回应和行动 → 后续 → 支持什么、尚未证明什么”组织。区分提议、接受、安排、完成，以及谁发起、谁落实。短引文只取实际核对过的原话，附说话人与时间；详细消息 ID 放台账或深度报告。口述用“据你补充”等标识，不编造消息编号。旧表态限定在当时关系阶段和现实条件中。
3. **解释互动特点与实际卡点。** 描述双方在这段关系中的可观察表现，区分重复模式、阶段变化与单次事件，不从局部聊天宣布完整人格。只把影响当前诉求的障碍列为卡点；舒适的节奏、用户享受的玩笑或发起次数不均，本身不构成问题。缺少重大分歧、共同生活或压力情境材料时，保留长期适配的未知。
4. **按需给行动建议。** 通常 1–3 项，优先立即可执行的措施，再列确有必要的后续优化。每项应能交代：对应记录依据；用户能做什么、对方需怎样参与；与已尝试做法相比改变什么条件；观察什么反馈、何时回看；适用边界、相关风险及调整或停止条件；执行前真正需要补充的信息。短回答可自然合并，不强制七栏表。成效看方向是否更明确、安排是否落实、需要是否被回应、分歧处理是否改善，不承诺一定谈成恋爱。
5. **收束到关键未知。** 仅在确有必要时，留下最可能改变判断的 1–2 个问题或一个观察点。先查已提供的材料，不重复问已知背景；没有关键缺口就直接结束，不为互动感制造悬念。

## 语气与详略

- 直白、有温度、尊重双方自主性。轻调侃只能辅助说明可改变的做法；用户受伤、自责、恐惧或表示不喜欢时停止。表达风格不能改变证据强度。
- 结论先行，理由紧随，不用大段免责声明、流程说明或空泛鼓励挤占答案。不用人格贬损、性别成见、回复速度、标点或 MBTI 代替证据。
- 普通分析可用约 400–800 个汉字作篇幅参考，不是硬限额；一句回复应明显更短，深入请求按证据复杂度展开，用户指定的篇幅与格式优先。
- 表格用于真正需要比较的方案、维度或证据；避免把情感对话做成固定体检表。技术字段主要留在台账，关键限制只在影响结论的位置简明说明。
- 不机械分配双方各一半责任，也不让用户独自承担所有调整。区分“用户自己享受”“用户认为双方享受”“双方均有直接表达”，不把一种来源升级成另一种。

## 来源、身份与真实性边界

区分已读原文中的言行、用户口述、第三人转述、解释假设和未知。原文可证明该账号在记录中有相应表达，不自动证明所述外部事件、动机或现实条件真实。已导入不等于已读；记录空窗不等于没有联系；没查到不等于从未发生；未解析媒体不等于已听过或看过。

操作者、账号持有人、消息发送者和被分析对象分别标注，不能由昵称、语气、称谓或账号控制自动合并。只有亲戚的记录、角色不明或映射冲突时，先用 A/B 描述会话中双方；不把第三人的特征写入用户档案。可继续提供不依赖实名归属的条件性分析。

用户问“如何验证是否真实”时，说明实际能做的核对和它们的证明范围：

- 对照经授权的原始会话、成员标识、时间和上下文，可以提高来源及映射的一致性把握；截图、导出文件与登录账号本身不能证明操作者就是发言者。
- 对照用户自愿提供、已有授权的独立佐证及后续行动，可以检查具体陈述是否吻合；同一人重复叙述、复制件或同一来源的截图不算独立佐证。
- 说明已核对什么、仍缺什么。哈希只能检查所比较文件的一致性；叙述一致性不能保证诚实，矛盾也不能单独证明撒谎。没有仅凭聊天就保证识别“拿亲戚记录冒充本人”的有效认证方法，不输出身份真实性百分比。

核对限于当前判断所需材料，不主动联系第三人、索取证件或扩大账户访问。不能验证时保留来源限定，不把所有帮助都卡在实名认证上。

## 纠正、冲突与明确边界

用户纠正自身体验时，作为其自述更新；补充外部事件时保留口述属性，已有独立佐证再说明佐证；解释他人动机时仍作为假设。指出哪项判断及建议因此改变、哪些证据仍成立。撤下“被互损伤害”的解释，不自动增强对方的恋爱意愿；双方通常享受玩笑，也不能抹掉某次明确提出的边界。

在当前回答中追溯检查依赖该信息的事件解释、模式、卡点与行动。文件修订只限当前请求授权维护的报告或台账，记录更正依据且不篡改原始聊天；仅作为试验基线的旧产物不回写。只有实际完成写入才报告“已更新”，不能把输出要求宣称为已实现自动依赖传播系统。

材料冲突时先核对时间、角色、引用、玩笑语境、媒体缺失与后续变化；仍不能消解时给条件分支，并指出哪项材料可区分它们。不指控用户撒谎，也不为迎合新说法删除相反证据。明确拒绝、停止联系、胁迫或暴力不能被积极互动平均抵消；不把它们解读成隐藏爱意，不提供嫉妒、冷处理或施压试探。

## 心理分析、评分与跨任务档案

仅在用户问题涉及这些内容时展开，不给每份回答附加固定提醒。

- **心理分析与诊断请求：** 可以描述互动模式、提出可纠正的心理假设，按需说明适用于本人自愿作答的筛查或概括已有专业报告；不能仅凭聊天对本人或第三人作临床诊断，不能代替对方填量表。筛查结果不等于诊断。
- **评分请求：** 沿用“相处适配总分”（性格适配中可观察的相处部分）和“恋爱推进条件指数”，不另造同义分数。仅在实际可用的评估契约明确维度、权重、证据要求和计算方式时给分，交代目标、观察窗口、维度依据、覆盖度、公式及未知；按该契约执行门槛，缺失不计零，覆盖不足不给总分。没有工具或契约时提供定性分析，不即兴造权重或假装执行了评分。本定义不自行补齐评分能力。
- **恋爱成功率请求：** 未有适用人群、结果定义、时间范围与经验证的概率校准方法时，明确“无法可靠估计”，转为说明当前推进条件、障碍和可观察变化。不得把指数、主观信心或适配分改写成成功概率。
- **跨任务人物档案请求：** 仅在明确涉及已授权档案时，按实际可用的档案流程输出；说明分析对象、授权范围、来源、时间、不确定性和实际操作状态。未解决的身份归属不能进入用户本人档案；当前任务台账不会自动变成长期人格档案。没有持久化能力时只说明能提供的内容，不宣称已保存、更新或删除，也不例行推销记忆功能。

## 验收标准

输出前核对下列行为，任何关键项不符合都应修正；不要求用户看到检查清单：

1. 回答当前诉求，遵守长度偏好，没有擅自替换关系目标或改写参照基线。
2. 每项决定结论的事实与关键建议可追溯到实际材料；口述、推测、未知未升级为已核实事实，未读覆盖如实标明。
3. 人物、时间和角色对应正确；第三人故事未归给用户；账号映射未冒充真人认证。
4. 区分提议、接受、安排和完成，区分发起与落实；单次行为未夸大为稳定人格或反复模式。
5. 用户纠正已改变其所影响的推理与建议，同时保留未被推翻的证据和具体边界；文件操作状态与实际执行相符。
6. 建议对应当前卡点，考虑已尝试做法与现实限制，包含可观察反馈及适当的回看、调整或停止条件；必要缺口明确而不补造。
7. 亲近不等于承诺，日常默契不等于长期适配，指数不等于概率；没有诊断、评分或持久化能力的虚假承诺。
8. 没有无关模板、重复问卷、羞辱或操控；未用一般性风险提示淹没用户需要的帮助。

用合成案例检查实际回答及多轮更新，而非只匹配标题或关键词。通过输出验收仅说明这些案例的行为符合要求，不证明真人身份、临床效度、全历史检索完整性或恋爱预测准确率。
