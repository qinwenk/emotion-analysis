# 关键场景检索与证据

用于寻找关系推进、倒退、修复及卡点，并定位其中用户情绪变化明显的场景。先找到事件，再读完整过程，最后交给[关系判断与互动表达](analysis-and-dialogue.md)深析。用户只问一次互动时限定该事件及必要背景，不自动扩成全历史体检。

## 先确定覆盖范围

复用已经核实的会话、双方账号/成员映射、时间范围与用户目标；映射未清先按[导入核验](chatlab-import.md)处理。按 [输出模式定义](output-mode.md) 区分操作者、账号持有人、发言者与分析对象；账号核对不是实名认证，角色未明时用 A/B 并保留歧义。聊天正文通过 `--format agent` 读取，保留隐私预处理；结构和计数可用 `--format json`、`--no-content`。不用 `--raw` 或 SQL 绕过正文预处理。

分清“导入范围”“实际看过的正文范围”和“深入核对过的事件”。只有读取并判断过内容的片段才能标为已扫描；统计、关键词命中数或摘要不能代替正文覆盖。分段工作时记录时间边界、已读消息定位、未读部分、截断和媒体缺口。预算不足就缩小本轮结论范围，不能把未读部分标成没有关键事件。

## 时间与主题两路找候选

关系全局请求先在指定范围按时间分批浏览，形成粗时间线，保留普通互动作对照；再围绕当前问题检索邀约落实、表达方向、支持与失落、边界、现实安排、冲突及修复。主题检索用于补回事件和反证，不替代时间覆盖。短句、平静表态和没有情绪词的安排变化也可能重要。

当前核实的 ChatLab CLI 0.37.7 有以下边界，执行时仍以帮助为准：

- `messages search` 是 LIKE 文字匹配，多关键词默认 OR；默认最近 20 个命中、上下文为 0。按需指定 `--match`、`--sort`、`--context` 和时间条件，不能把它当语义搜索，也不能把第一页当全量。
- `messages list` 先取最新页，页内按时间展示；显示顺序不代表已经从历史起点看起。按时间窗口浏览，遇到 `meta.hasMore` 时用返回的 `meta.nextCursor`、相同查询条件续页。检查返回范围和重复边界，不能仅凭游标为空推断所有正文都已呈现。
- 单消息、总消息数和总 token 预算都可能截断输出。`--full` 只取消单消息长度截断，不取消总预算；`--max-messages` 还会限制搜索后的上下文展开。发现缺尾、截断提示或计数不符时，缩小时间窗或分批补读，记录仍缺的部分。

可以用“我很失望”等直接表达定位，也要在分段阅读中判断“期待形成后没有落实”等事件含义。当前方法由 agent 使用已有查询工具完成，没有新增向量索引或自动情绪检测器；语义相近但用词不同的情况需要改写检索词或回到时间浏览。

## 从命中扩成事件

以可定位的消息为锚点，先取邻近上下文，再检查起因、双方回应和后续。`messages context --id` 使用实际返回的单条数值 ID；范围标记只用于展示，不能作为查询 ID。`--window` 默认前后各 10 条、最大 100；仍未看全时改查相邻时间窗口，并沿引用、约定或后续提及补查。

事件边界随话题和行动确定：一次取消可能隔天才改期，一次争执可能在下一轮沟通修复。固定条数或时间间隔只能帮助切段，不能证明事情已经结束。标记未找到起因、回应缺失或后续未知；没有查到回复不等于对方故意沉默。无法读取的语音、图片、撤回内容不得补写。

按需要补查同类历史事件，核对这次是变化、重复还是偶发。保留当时的关系阶段；回顾分析可以追踪后续，重建“当时能判断什么”时不得偷用后来才发生的信息。核对近期状态，但热情更新不能自行撤销尚未改变的明确边界。

## 分开记录三种判断

关系意义看事件前后是否改变了双方可确认的方向、互惠、边界、兑现情况或现实可行性。节点可以是靠近、退回、修复，也可以是某个重要条件得到澄清；必须说明前后差别，不能仅因谈到恋爱就标为推进。

用户情绪看其明确自述，以及相对本人在相近阶段、相似情境下的表达变化。分别保留双方，不能把对方激动算成用户情绪。比较多个普通片段；短句、连发、回复间隔只能提供线索，需考虑日常习惯、忙碌、记录缺失和用户纠正。开心、释然与紧张也可能值得深析，不能只收集负面情绪。未表达的内心状态保留未知。

证据充分度看身份、起因、原话、回应、后续和反证是否可核实。这三项不能合成一个“情绪分”排序：平静的拒绝或异地安排可能关系意义很高；激烈讨论游戏未必涉及关系；用户强烈难受但起因缺失，需要先支持并补问，而不是先作归因。

## 留下可复查的事件记录

多事件分析可在本次私人工作目录保存简短台账，短请求直接在当前上下文维护即可。下列是字段提示，不是强制报告模板：

| 信息 | 记录要点 |
| --- | --- |
| 定位与范围 | 会话、事件编号、实际时间、真实消息 ID；已读与缺失部分 |
| 来源与归属 | 原文、口述或转述；佐证状态及角色歧义；口述不编消息 ID |
| 发生了什么 | 起因、双方行动、回应与后续；提议/接受/安排/完成、发起/落实分开；事实和摘要推测分开 |
| 关系意义 | 前后变化、候选卡点；支持与不支持当前解释的证据编号 |
| 用户情绪 | 明确自述或表达变化、本人对照片段、仍待确认的体验 |
| 待解决问题 | 哪个未知会改变建议，是否值得补查或补问 |

原话只引用核对过的必要短句，并保留说话人、时间和编号。区分本人表达、转述、引用与第三人故事；摘要只负责定位，不取代原始证据。只为本任务保存必要信息，台账不作为跨任务人格档案，也不进入公开仓库。

时间、次数与现实条件保留原文精度：模糊期限不能换成确定起止日期，计划不能写成已经兑现，单次事件不能扩成反复模式。对方对外部情况的解释仍是其说法，不自动当作独立核实的事实。若这些条件影响建议，列为待确认项再比较方案。

## 选出值得深析的场景

合并同一次事件的重复命中，保留修复和反例，不让一段争执占满候选。检查早晚阶段和双方是否有覆盖；偏重近期困境，但不丢掉仍影响当前选择的旧约定。用户指出的重要事件即使未命中关键词，也要优先核查。

先围绕当前目标确定最有证据的节点与卡点，再挑出其中用户体验强烈或反复受影响的事件深析；安静但决定关系方向的事实仍须交代。每个重点场景应能回答“为什么选它、依据在哪里、还缺什么”。随后按分析参考解释互动过程、形成针对性行动和观察反馈，不用更多检索延迟已经能给出的帮助。
