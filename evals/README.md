# 关键场景评测

本目录提供 6 个完全虚构的行为冒烟案例，用来检查「关系节点与卡点 → 用户情绪关键场景 → 深析 → 当前可执行行动」这条流程。它不包含真实聊天，不训练模型，也不证明真实微信场景中的准确率。原有 55 项合成工具测试仍负责解密、解析与数据约束；这两类验证不能互相替代。

- [cases.json](cases.json)：给被测模型的请求、背景、参与者、消息与可选补充。没有参考答案。
- [rubric.md](rubric.md)：给评审的证据锚点、可接受判断和错误边界，不与案例一同给被测模型。

## 运行方式

1. 固定本次要比较的 skill 版本、模型和设置。每个案例分别开新上下文，加载该版本的 `SKILL.md` 及按需参考，只提供该案例的 `user_request`、`participants`、`context` 和 `messages`。说明这是虚构测试，只分析提供的材料，不调用真实 ChatLab、不执行导入或其他外部动作。
2. 首轮不提供 `follow_up`。取得并保存回答后，若案例有 `follow_up`，再在同一案例对话中送入该补充，保存更新后的回答。不要把完整 JSON 连同补充提前发送，避免模型预知关键纠正。
3. 新旧版本用相同输入分别运行，不让后一版本看到前一版本的回答。将输出随机标为 A/B，再交由评审依据 `rubric.md` 对照原始消息；重要或不稳定案例可重复运行。
4. 记录具体遗漏、误报、证据错误、补问与行动差异。保留原始回答，不以词语或标题正则代替行为评估，不把更长、更像报告的答案自动判为更好。
5. 如果结果用于修改 skill，这些案例成为开发集。另留未参与修改的案例作检验，同一对人的不同片段应放在同一组；正式评估还需包含人工标注的授权真实事件和普通对照时段。

这些案例的证据 ID 是文件内部标识，不是 ChatLab 数字消息 ID。它们用于核对引用，不能直接传给 `clb messages context --id`。

## 当前覆盖与缺口

涵盖积极投入、无关兴奋干扰、跨天修复、平静边界、享受互损的纠正、现实规划压力，以及语音/上下文缺失。这里提供的是整理好的短材料，**没有验证真实 CLI 分页、截断恢复、全历史扫描或自动场景召回**；这类能力应另用隔离的合成会话和工具记录进行验证。

评测输出保存在公开仓库之外。未来加入授权真实案例时，默认私有保存、去除可识别信息，并将可公开的抽象经验与原始材料分开；不要把运行日志或真人关系报告提交到本仓库。
